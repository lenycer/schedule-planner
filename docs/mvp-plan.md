# 간호사 월간 스케줄 작성 프로그램 1차 개발 계획

## 1. 목표

24~26명 규모의 간호사 인력을 대상으로 월간 3교대 스케줄을 자동 생성하는 MVP를 개발한다.

- 출력 형식: `md` 요약 리포트 + `csv` 스케줄 파일
- 대상 근무: `D`, `E`, `N`, `O`, `P`
- 핵심 목표:
  - 법적/운영상 명백히 불가한 패턴 차단
  - 요일별 필요 인원 충족
  - 불합리한 패턴 최소화
  - 사람이 후편집 가능한 결과 생성

## 2. 근무 코드 정의

| 코드 | 시간 |
| --- | --- |
| D | 07:00 ~ 15:30 |
| E | 15:00 ~ 23:30 |
| N | 23:00 ~ 익일 07:30 |
| O | 휴무 |
| P | 10:00 ~ 18:30 |

## 3. 제약 조건 정리

### 3.1 하드 제약

아래 규칙은 반드시 만족해야 한다.

1. `N` 연속은 최대 3회까지만 허용
2. 연속 근무는 최대 5일까지만 허용
3. 월간 `N` 횟수는 8회 이하
4. `NOD` 패턴 금지
5. `NE`, `ND`, `NP` 패턴 금지
6. 요일별 필요 인원 반드시 충족
7. 특정인원 한명은 평일(월~금) D 근무 고정 => 데이 중앙
8. 특정인원 한명은 평일(월~금) E 근무 고정 => 이브 중앙
9. 중앙 근무자들은 입력값으로 받음.

### 3.2 소프트 제약

아래 규칙은 최대한 피하되, 전체 해를 만들기 위해 필요하면 제한적으로 허용한다.

1. `EOD` 패턴 최소화
2. `NOE` 패턴 최소화
3. 동일 패턴 5연속 최소화
4. 단, 평일 `D` 또는 `E` 인원 중 1명은 동일 패턴 5개 허용 가능

## 4. 대표적인 불가 패턴 검토

### 4.1 법적 이슈 또는 강한 운영 리스크

아래 항목은 한국 근로기준법 및 교대제 운영 상 주의가 필요하다.

1. `NE`, `ND`, `NP`
   - `N` 종료가 07:30인데 같은 날 `D(07:00)`, `P(10:00)`, `E(15:00)`로 이어지면 충분한 연속 휴식이 없다.
   - 특히 `보건업`은 근로기준법 제59조에 따른 특례를 쓰는 경우에도 다음 근로 개시 전 `11시간 이상 연속 휴식`이 필요하다.
   - 따라서 하드 제약으로 두는 것이 타당하다.

2. 장기 연속근무
   - 6일 이상 연속근무는 피로 누적과 오류 가능성을 높인다.
   - 법령 해석은 근로계약, 휴일 부여 방식, 특례 적용 여부에 따라 달라질 수 있으므로 MVP에서는 `5일 초과 연속근무 금지`를 강제하는 편이 안전하다.

3. 과도한 야간 편중
   - 월 `N` 9회 이상은 피로도와 형평성 이슈가 커진다.
   - 병원 운영 룰로 월 `N <= 8`을 하드 제약으로 유지하는 것이 합리적이다.

4. 주간 총근로시간 초과 가능성
   - `D/E/N/P` 모두 실근무 8시간 이상으로 보일 가능성이 높아 주간 연속 배치가 많으면 1주 40시간, 연장 포함 52시간 한도를 쉽게 건드릴 수 있다.
   - MVP에서는 주차별 총 근무시간 검증 로직을 반드시 넣는다.

### 4.2 불합리 패턴

1. `NNNN`
   - 사용자 요구상 금지
   - 야간 적응과 회복 측면에서도 일반적으로 과도하다.

2. `NOD`
   - 법적으로 즉시 금지된다고 단정하기는 어렵지만, 야간 후 회복일 1회만 두고 바로 이른 `D`로 복귀시키는 패턴이라 운영상 비합리 패턴으로 볼 수 있다.
   - 사용자 정책상 하드 제약으로 반영한다.

3. `EOD`
   - `E` 종료가 23:30이라 생체리듬 회복이 밀린 상태에서 하루 쉬고 이른 `D`로 복귀하는 흐름이다.
   - 하드 금지는 아니지만 소프트 제약으로 패널티 부여가 적절하다.

4. `NOE`
   - `N` 후 하루 쉬고 다시 늦은 근무로 들어가면 회복 리듬이 불안정해질 수 있다.
   - 소프트 제약으로 관리하는 것이 적절하다.

5. `DDDDD`, `EEEEE`, `PPPPP`
   - 특정 근무 고착으로 피로와 불만 가능성이 높다.
   - 기본적으로 소프트 제약으로 막고, 예외 규칙은 평일 `D/E` 충원 목적에 한정한다.

## 5. 요일별 수요 정의

### 평일(월~금)

- `D`: 6명
- `E`: 5명
- `N`: 4명
- `P`: 1명
- 나머지: `O`

### 주말(토~일)

- `D`: 4명
- `E`: 5명
- `N`: 4명
- `P`: 1명
- 나머지: `O`

## 6. MVP 범위

### 포함

1. 월간 캘린더 생성
2. 24~26명 랜덤 이름 인력 자동 생성
3. 하드 제약 검증
4. 소프트 제약 점수화
5. 요일별 인원 충족 스케줄 생성
6. 결과 `csv` 출력
7. 결과 요약 `md` 리포트 출력

### 제외

1. 개인별 휴가 신청 반영
2. 경력/파트/프리셉터/수간호사 등 직급 스킬믹스
3. 선호 근무 반영
4. 공휴일 가중치
5. UI
6. 다병동 동시 최적화

## 7. 추천 설계

### 7.1 입력

`nurse_pool.csv`

- `nurse_id`
- `name`
- `employment_type`
- `max_nights_per_month`
- `max_consecutive_work_days`

`scheduler_config.yaml` 또는 `json`

- 대상 연월
- 총 인원 수
- 요일별 수요
- 하드 제약
- 소프트 제약 가중치

### 7.2 출력

`monthly_schedule_YYYY_MM.csv`

- 행: 간호사
- 열: 날짜별 근무코드

`schedule_report_YYYY_MM.md`

- 하드 제약 위반 여부
- 소프트 제약 점수
- 인력별 `N` 횟수
- 인력별 연속근무 최대치
- 요일별 충족률

## 8. 알고리즘 1차안

MVP는 완전 자동 최적화보다 "생성 + 검증 + 재시도" 구조가 적합하다.

1. 날짜별 필요 슬롯 생성
2. `N`부터 우선 배치
   - 제약이 가장 강하므로 먼저 배치
3. `E`, `D`, `P` 순으로 배치
4. 남는 인원은 `O` 배정
5. 하드 제약 검사
6. 소프트 제약 점수 계산
7. 실패 시 시드 변경 또는 로컬 스왑으로 재탐색

MVP 구현 우선순위는 아래와 같다.

1. 백트래킹 + 휴리스틱
2. 필요 시 로컬 서치(스왑)
3. 2차 이후 OR-Tools CP-SAT 검토

## 9. 검증 로직

필수 검증 항목:

1. 일자별 필요 인원 충족 여부
2. 간호사별 하루 1코드 배정 여부
3. `NE`, `ND`, `NP` 금지 여부
4. `NOD` 금지 여부
5. `N` 3연속 초과 여부
6. 연속근무 5일 초과 여부
7. 월 `N` 8회 초과 여부
8. 주차별 총근로시간 초과 여부
9. 소프트 제약 발생 횟수

## 10. 1차 개발 일정안

### 단계 1. 규칙 엔진

- 근무 코드/시간 정의
- 패턴 판별기 구현
- 하드/소프트 제약 분리

### 단계 2. 스케줄 생성기

- 월간 날짜 생성
- 요일별 필요 인원 생성
- 랜덤 초기 배치
- 제약 기반 재배치

### 단계 3. 검증기/리포터

- 위반 검출
- 통계 계산
- `csv`, `md` 출력

### 단계 4. 샘플 데이터/테스트

- 24명, 25명, 26명 케이스
- 월 28일, 30일, 31일 케이스
- 실패 케이스 재현용 시드 테스트

## 12. 법적 검토 메모

이 항목은 법률 자문이 아니라 MVP 설계 시 반영할 최소 체크포인트다.

1. 근로기준법 제50조
   - 1주 40시간, 1일 8시간 원칙
2. 근로기준법 제54조
   - 4시간 30분, 8시간 1시간 이상 휴게 필요
3. 근로기준법 제56조
   - 야간근로(22:00~06:00) 가산수당 필요
4. 근로기준법 제59조
   - 보건업 특례 시에도 다음 근로 전 11시간 연속 휴식 필요

따라서 MVP는 최소한 아래를 시스템 체크 항목으로 포함해야 한다.

1. 주간 총근로시간 경고 또는 차단
2. 야간 후 다음 근무까지 휴식시간 계산
3. 야간수당 산정용 데이터 추출 가능 구조

## 13. 1차 산출물 정의

1. 스케줄 생성 스크립트 1개
2. 샘플 인력 CSV 1개
3. 월간 결과 CSV 1개
4. 검증 리포트 MD 1개
